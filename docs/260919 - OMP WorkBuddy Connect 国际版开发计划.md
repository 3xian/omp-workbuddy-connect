 OMP WorkBuddy Connect 国际版开发计划

 建议采用“先验证宿主契约 → 打通完整认证闭环 → 迁移模型与请求兼容 → 完成命令和 UI → 真实场景验收”的顺序。

 这不是简单的包名替换，而是一次凭据所有权和请求责任边界的迁移。最大风险不是 Streaming，而是 Bearer Token、账号身份
 Header、模型注册状态在登录、刷新、切换范围和退出后是否始终一致。

 以下计划依据需求全文、仓库现有实现及 OMP v18.2.6 Provider 类型与 ModelRegistry 源码制定。本次仅分析和制定计划，未修改代码。

 二、第一性原理：必须守住的五条不变量

 ### 1. 一个凭据事实来源

 ```text
WorkBuddy 登录 / 刷新协议
          ↓
    OMP AuthStorage
          ↓
模型认证、身份 Header、积分查询
 ```

 插件不得在正常调用时从环境变量、桌面登录或自存文件中“选一个更新的 Token”。

 否则，即使每个局部函数正确，整体仍可能产生账号串用和退出后重新登录的假象。

 ### 2. Token 与身份必须成套使用

 一次请求中的：

 - Authorization
 - X-User-Id
 - X-Enterprise-Id

 必须来自同一账号。

 v1.0 仅承诺单账号。顺序换号也必须验证，不能因为不支持多账号轮换，就忽略旧模型对象保留旧身份 Header 的风险。

 ### 3. 模型元数据是协议能力声明

 thinking、图片输入、context 和 max tokens 不是展示字段，而是影响真实请求生成的契约。

 不能因为模型名称相似，就套用官方直连 API 的能力；以 WorkBuddy Gateway 实际支持为准。

 ### 4. 插件只承担差异

 OMP 负责认证解析、标准消息转换、Streaming、工具流解析、Retry 和 Abort。

 插件只负责：

 - WorkBuddy OAuth 协议；
 - 固定及身份 Headers；
 - WorkBuddy 模型目录与能力映射；
 - 已确认必需的 payload 差异；
 - 积分与交互。

 不引入自定义 transport、代理或全局 fetch 拦截。

 ### 5. 可选功能故障不得破坏核心调用

 积分服务不可用、Widget 更新失败，不得阻塞启动或模型调用。

 但认证不完整不能按“非致命错误”处理：必须明确拒绝继续使用错误身份。

 三、需要调整或明确的需求点

 ### 1. 第一条真实请求就必须包含完整身份

 需求第 40 节把 Identity 放在 Provider Skeleton 之后，但第 13 节明确身份 Headers 必需。

 调整：OAuth、Bearer、身份 Header 和刷新保留身份合并为第一个端到端里程碑。 不以“只有 Token 的请求”作为阶段成功标准。

 ### 2. P1 是实施顺序，不是可裁剪范围

 需求第 39 节已将以下能力纳入 v1.0 完成条件：

 - /workbuddy、free/all、logout；
 - 积分查询；
 - main agent/subagent。

 因此它们不能以“P1”名义延期。P2 才是本版明确不做的内容。

 ### 3. modifyModels() 需要显式过滤 Provider

 核对 OMP 源码后，发现其 modifier 接收的是完整模型目录，不是只有 WorkBuddy 模型。

 实现必须保留其他 Provider 模型，仅修改：

 ```ts
model.provider === "workbuddy"
 ```

 这应作为跨 Provider 隔离的回归约束。

 ### 4. 不能只在 modifyModels() 抛错来阻断非法认证

 OMP v18.2.6 的 ModelRegistry 会捕获 modifier 异常，并继续提供未投影目录。

 因此：

 - 登录时校验身份完整；
 - 刷新时保留并校验身份；
 - getApiKey() 返回 Token 前再次校验必要身份；
 - 在真实请求链上验证缺失身份时确实不发起 Chat 请求。

 “UI 显示错误”不等于“请求已安全阻断”。

 ### 5. 模型缓存与付费展示需要明确语义

 推荐沿用现有来源，但补充可观察行为：

 - 缓存缺失或损坏：使用现有内置清单，并明确显示 fallback 来源；
 - all：表示全部当前可识别模型，不宣称覆盖完整服务端目录；
 - 价格未知：不能据此判定免费；
 - 免费集合为空：明确提示，不将缓存中已标价付费的模型重新当成免费；
 - cost: 0：如果仅是宿主格式占位，不能对用户表达为“不消耗积分”。

 ### 6. 版本命名不要自动回退

 当前 package.json 为 1.1.5，需求称“v1.0”。

 建议把需求 v1.0 作为适配功能基线；实际发布版本按 Fork 发布渠道确定，不直接把包版本降为 1.0.0。

 四、分阶段实施计划

 ### M0：恢复基线，验证 OMP 契约

 目标：让后续开发基于真实宿主行为，而非文档假设。

 工作项：

 1. 修复当前语法错误，恢复模块导入。
 2. 固定开发验证依赖为 OMP 18.2.6，避免 * 引入未验证 API。
 3. 核实 OAuth 类型导出路径及 credential 字段。
 4. 核实以下行为：
   - getApiKey()、refreshToken()、modifyModels() 的调用和错误传播；
   - AuthStorage 的读取、删除及刷新入口；
   - free/all 重注册是否更新模型选择器和已选模型；
   - Headless、subagent 是否加载扩展和 payload hook。
 5. 建立需求—实现—验收对应表。

 完成门槛：

 - 模块可导入；
 - 基于 18.2.6 的类型检查通过；
 - 官方宿主可加载扩展；
 - logout、积分认证和模型重注册已有公开 API 路径，不需要改 OMP 或读写私有存储文件。


 ### M1：完整认证与身份闭环

 目标：使用一个经确认可用的 WorkBuddy 模型，完成登录、对话、刷新、重启和退出。


 1. 保留现有 Plugin Auth 协议，适配 OMP callbacks。
 2. 将协议响应映射为：
   - access
   - refresh
   - expires
   - accountId
   - orgId
   - 可用的显示身份字段。
 3. 取消正常链路中的 saveOwn/current/resolveCred 和桌面凭据竞争。
 4. 刷新仅使用传入的 OMP credential，保留账号身份。
 5. Provider 固定 Header 固定到国际版，不信任 credential 中的动态 domain。
 6. getApiKey() 返回 access token，由 OMP 负责 Bearer。
 7. modifyModels() 只为 WorkBuddy 模型注入身份 Header。
 8. 删除 Marker、before_provider_headers。
 9. 先实现 logout 的认证删除能力，UI 细节后置。
 10. 处理授权拒绝、轮询超时、取消、刷新失效、身份缺失；不记录 Token。


 - 登录后首条真实 Streaming 请求成功；
 - 重启无需重新登录；
 - Token 过期后自动刷新，身份不丢失；
 - 身份缺失时 Chat 请求被阻断；
 - logout 后不能继续使用旧认证，也不会回退桌面凭据；
 - 账号 A 退出、账号 B 登录后，不再发送 A 的身份。

 ### M2：模型目录、Thinking 与 Vision

 目标：模型选择器声明的能力与真实请求一致。

 工作项：

 1. buildPiModels() 迁移为 buildOmpModels()，更新全部调用者。
 2. 使用真实 ProviderModelConfig 类型约束输出。
 3. 删除 thinkingLevelMap，映射 OMP thinking。
 4. 区分：
   - 不支持 reasoning；
   - 支持指定 effort；
   - 可关闭 thinking；
   - 不允许关闭 thinking。
 5. 覆盖 minimal/low/medium/high/xhigh/max 的实际支持集合。
 6. 不在插件重复生成标准 reasoning_effort。
 7. 根据产品配置设置图片能力，必要时覆盖 stripImageInput。
 8. 保留 DeepSeek token 上限约束，避免目录与请求预算矛盾。
 9. 实现缓存异常和 free/all 空集合的明确行为。
 10. 删除 refreshModels()，通过重新注册更新模型集合。

 完成门槛：

 - name、reasoning、context、max tokens、input 正确；
 - 不发送模型不支持的 effort；
 - 不允许关闭的模型不会收到非法 off；
 - 支持图片的模型完成真实图片输入；
 - free/all 更新后，身份 Header 和 OAuth credential 不丢失。


 ### M3：Gateway Payload 与工具闭环

 目标：保留必要兼容，不再重复实现宿主。


1. 保留 `before_provider_request`，按 request-bound `ctx.model.provider` 过滤 WorkBuddy wire compatibility。
2. 每项旧变换分别收集删除后 Gateway 失败证据；仅保留有证据的最小差异。
3. 移除由 OMP 正确承担的标准转换。
4. 将活动 scope、切换期与 retained-model fail-closed guard 放在 WorkBuddy-bound `resolveHeaders`，不用 hook 异常阻断 transport。
5. 验证下一轮请求保留正确的 tool call ID、工具结果和消息关联。
6. 验证当前与历史同 ID 的非 WorkBuddy 请求完全不变，不改用自定义 transport。


 - 单工具、连续工具、多工具闭环通过；
 - tool arguments 流式拼接正常；
 - auto、named tool choice 等已有兼容路径正常；
 - reasoning 历史重放不被 Gateway 拒绝；
 - text/reasoning/tool delta、usage、[DONE]、HTTP Error、Abort、Retry 在宿主链路下正常。


 ### M4：命令、积分与 UI

 目标：管理功能正确，并与核心调用解耦。


 1. /workbuddy 展示登录状态、账号、积分、套餐、scope、模型数和 Provider 状态。
 2. /workbuddy free|all：
   - 构建新目录；
   - 更新 Provider 和 hook 的 ID 集合；
   - 持久化 scope；
   - 同步 Widget；
   - 不改 credential。
 3. 对当前模型被移出 scope 的情况明确提示，不自动切换到付费模型。
 4. /workbuddy logout 调用认证删除路径，清理 Widget/status。
 5. 积分认证从 OMP 获取，不创建第二套刷新器。
 6. 积分查询失败显示 unavailable，而不是零积分。
 7. session_start/turn_start 更新显示，启动不等待积分网络请求。
 8. ctx.hasUI === false 时跳过 UI。
 9. 防止迟到的积分响应在 logout 或切换模型后恢复旧 Widget。
 10. 设置路径使用宿主目录规则，尊重 PI_CODING_AGENT_DIR。


 - 四个必需命令全部可用；
 - Billing API 故障不影响对话；
 - logout 后后台响应不会恢复旧账号状态；
 - scope 重启后保持；
 - 无 UI 模式不访问交互组件。

 ### 测试分层

 保留为永久回归测试的高风险行为：

 - 刷新后身份字段保留；
 - 不完整身份不能获得可发送请求的认证；
 - modifier 不污染其他 Provider；
 - payload hook 不污染非目标模型；
 - reasoning 清理不破坏工具消息；
 - free 模式不选入明确收费模型；
 - Billing 慢或失败不阻塞启动；
 - logout 后迟到响应不恢复账号 UI。

 现有两个测试分别保护 Provider 隔离和启动非阻塞，行为有价值，应迁移到新认证链，而不是继续依赖旧凭据文件。

 真实 OMP 冒烟验证：

 用于证明注册、认证解析、Headers、模型重注册和 subagent 扩展加载。测试替身无法证明这些宿主行为。
